# 轉存成 Word（v1.0.42）設計

日期：2026-11-13　狀態：使用者說「不用先問我，有問題可以先以你的判斷先做」，以下都是我的決定

## 目的
使用者：「PDF 轉存成可編輯的 Word 檔」「可能比較困難，可以把不足的方面滿足再做／我想要這個功能穩定一點」。之前跟使用者說明過的做法：電腦有 Word 時交給 Word 本身的 PDF 轉換（最穩定）；沒有 Word 時用程式內建的轉換（文字、段落、圖片、掃描頁先文字辨識；表格與複雜版面較弱）。

## 做法
- 採用：兩條路，同一個入口。
  1. **這台電腦有 Microsoft Word（2013 以後）**：交給 Word 本身的 PDF 轉換。主程式用 PowerShell 透過 COM 在背景開 Word（不顯示視窗）：唯讀開啟 PDF、不確認轉換 → 另存成 .docx → 關閉 Word。版面最接近原本、表格也會轉。
  2. **沒有 Word**（或使用者選內建）：程式內建的轉換，自己寫出 .docx（OOXML，用 pako 壓縮 zip）。
- 不採用：線上轉換服務（檔案要上傳，違反「檔案只在電腦裡處理」）；LibreOffice（使用者電腦不一定有，而且它開 PDF 是用 Draw，轉出來是一堆文字框）。

## 設計
1. **入口**：工具列「輸出」分段按鈕加〔轉存 Word…〕（`ACTION_MENUS.output`）。
2. **轉存成 Word 視窗**：
   - 頁面：全部／指定範圍（`parseRange`，跟轉存圖片一樣）。
   - 轉換方式：「用 Microsoft Word 轉換（最接近原本的版面）」／「程式內建轉換」。有 Word 時預設 Word；沒有 Word 時第一項停用並寫「這台電腦沒有 Word」。
   - 掃描頁：「先做文字辨識（可以編輯文字，比較慢）」預設勾選；不勾就把掃描頁當成一張圖片放進去。（只有內建轉換用得到；Word 轉換時 Word 自己處理。）
   - 〔取消〕〔轉存〕→ 先選擇存檔位置（預設：原檔所在的資料夾、原檔名.docx；不能選原本的 PDF）→ 才開始轉換，進度（第 N／M 頁、「Word 轉換中…」）、〔取消〕可以停止 → 完成後提示「已轉存成 Word：檔名」，附〔開啟〕（用預設程式開 .docx）。
3. **轉的內容是目前看到的文件**（含還沒存檔的修改）。我們的註解（文字方塊、圖形、戳記、螢光筆、簽名、填好的表單欄位）先「壓平」到頁面上（依 PDF 規格把外觀畫進頁面內容），這樣 Word 和內建轉換都看得到；便利貼、連結、隱藏的註解、隱藏圖層上的東西不轉。原本的 PDF 不會被修改（壓平只在一份暫時的副本上）。
4. **內建轉換**（每一頁）：
   - 文字：pdf.js 的文字內容 → 行（同一條基線，中間空很大就分開）→ 閱讀順序（XY 切割：先找跨整區的上下空隙，再找欄間空隙，左欄先）→ 段落（字級相近、行距正常、左邊對齊或上一行寫滿就接起來；中文接起來不加空白，英文加空白）。保留字級、粗體、斜體（看字型名稱）、字型（常見的中文字型對應到 Windows 的字型：細明體、正黑體、標楷體；英文：Times New Roman、Arial；其他用預設）、置中與靠右。
   - 圖片：頁面上的圖片（跟〔擷取圖片〕同一套找法）裁切成 PNG，依位置插在段落之間（獨立一段、原尺寸）。
   - 掃描頁（整頁幾乎只有一張圖、沒有文字）：文字辨識（跟尋找與取代的掃描頁辨識同一套）→ 同樣組成段落；不辨識時整頁放一張圖片。
   - 每一頁一個分節（頁面大小、方向跟原本一樣），頁與頁之間分頁。
   - 多欄：照閱讀順序（左欄再右欄）由上而下排成一欄，縮排以那一欄的左邊為準（右欄的段落不會被推到頁面中間）。
   - 已經做過文字辨識的掃描檔（整頁圖片上有看不見的文字）：直接用那層文字，整頁的底圖不放進去（不然文字會出現兩次）。
   - 不做：表格偵測、保留多欄版面、文繞圖、頁首頁尾、文字顏色、向量圖形（線條、色塊）。
5. **Word 轉換的細節**（`main.js`）：
   - 找 Word：讀登錄 `HKCR\Word.Application\CurVer`（`Word.Application.15` 以上才有 PDF 轉換）。
   - 轉換：壓平後的 PDF 寫到暫存資料夾 → `powershell -NoProfile -NonInteractive -ExecutionPolicy Bypass -File …ps1`，路徑用環境變數傳（中文路徑不會亂碼）。腳本：`Word.Application`、`Visible=false`、`DisplayAlerts=0`、`Documents.Open(in, ConfirmConversions=false, ReadOnly=true, AddToRecentFiles=false)`、`SaveAs2(out, 16)`、`Close(0)`、`Quit(0)`。Word 的「Word 現在會將您的 PDF 轉換成可編輯的 Word 文件」提示：轉換前把 `HKCU\Software\Microsoft\Office\<版本>\Word\Options\DisableConvertPdfWarning` 設成 1，轉完還原原本的值。
   - 時間上限 10 分鐘；〔取消〕結束 PowerShell 並關掉這次開的 Word（命令列有 `/Automation` 而且是轉換開始後才啟動的 WINWORD.EXE）。
   - 失敗（Word 出錯、逾時）：提示原因，並問要不要改用內建轉換。
   - 暫存檔轉完就刪。
6. 網頁版（沒有主程式）：只有內建轉換，存檔用下載。

## 不做（這版）
- 表格、多欄版面、文字顏色、向量圖形的轉換（內建轉換）。
- Word 以外的轉換程式（WPS、LibreOffice）。
- .doc（舊格式）、.rtf、.odt。

## 測試（新檔 `tests/e2e/word.mjs`）
- 內建轉換：兩頁的 PDF（第 1 頁：標題、兩段文字（中英）、粗體、一張圖片；第 2 頁：橫向）→ 轉存（存檔視窗在測試裡攔下）→ 解開 .docx：`document.xml` 有標題與兩段文字（段落數、順序、粗體、字級）、一張圖片（`word/media/*.png`、`<w:drawing>`）、兩個分節（第 2 節橫向）；`[Content_Types].xml`、關聯檔齊全。
- 壓平：先用文字方塊工具加一段文字、畫一個矩形 → 轉存 → 文字方塊的文字在 `document.xml` 裡；原本的文件沒有改變（復原步驟數不變、還沒存檔的狀態不變）。
- 掃描頁：一頁整頁圖片的 PDF → 勾選文字辨識 → `document.xml` 有辨識出的文字；不勾 → 一張整頁圖片。
- 頁面範圍：只轉第 2 頁 → 只有一個分節。
- Word 轉換：主程式的 `word:convert` 在測試裡換成假的（Linux 沒有 Word）：視窗在「有 Word」時預設 Word、送出的 PDF 是壓平後的、完成後有〔開啟〕；「沒有 Word」時第一項停用。真正的 Word 轉換要在使用者的 Windows 電腦上確認（跟列印一樣，記在 HANDOFF）。
