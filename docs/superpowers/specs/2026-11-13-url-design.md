# 從網頁開啟 PDF（v1.0.40）設計

日期：2026-11-13　狀態：使用者說「不用先問我，有問題可以先以你的判斷先做」，以下都是我的決定

## 目的
使用者：「之後再新增開啟檔案的來源可以直接從網頁」。HANDOFF 列了三種可能：貼上網址下載後開啟、從瀏覽器把 PDF 連結或檔案拖進程式、在瀏覽器裡選「用 PDF 工作台開啟」。

## 做法
- 採用：(1) 貼上網址開啟；(2) 從瀏覽器把 PDF 的連結拖進程式視窗也能開。兩種都由主程式下載（跟著轉址、看系統的 Proxy），下載到記憶體、確認檔頭是 `%PDF` 才開，在新分頁打開，檔名取自伺服器給的檔名或網址的最後一段。
- 已經可以的：從瀏覽器的下載列把下載好的 PDF 拖進來（就是一般的檔案拖放）；檔案總管「開啟檔案」用 PDF 工作台（檔案關聯，已有）。
- 不採用：瀏覽器擴充功能（要另外安裝、每種瀏覽器各做一份，維護成本高）。

## 設計
1. **入口**：工具列「開啟」改成分段按鈕：〔開啟檔案…〕（Ctrl+O）〔從網址開啟…〕（Ctrl+Shift+O）；歡迎畫面多一個〔從網址開啟〕。
2. **從網址開啟視窗**：輸入框（打開時如果剪貼簿裡是 http／https 網址就先填好，經主程式讀剪貼簿）、〔取消〕〔開啟〕；格式不對（不是 http／https）顯示紅字。開啟時顯示「下載中…（已下載 N MB）」，可以取消。
3. **下載規則**：只接受 http、https；跟著轉址；上限 500 MB（超過就停並提示）；60 秒沒有收到資料就停；下載完確認開頭 1 KB 內有 `%PDF`，不是就提示「這個網址下載到的不是 PDF 檔（可能需要登入或是網頁）」。
4. **開啟後**：新分頁，名稱是檔名；沒有原檔路徑，所以和範例文件一樣，存檔時選位置另存新檔。
5. **拖曳連結**：把連結（`text/uri-list`）拖進視窗、沒有檔案時：是 http／https 網址就照上面下載開啟（不論副檔名，下載後看檔頭）。

## 不做（這版）
- 需要登入的網址（Cookie、帳號）：提示可能需要登入，請先在瀏覽器下載再拖進來。
- 瀏覽器擴充功能、自訂通訊協定（`pdfeditor://`）。

## 測試（新檔 `tests/e2e/open-url.mjs`，測試裡開一個本機 HTTP 伺服器）
- 〔從網址開啟…〕輸入 `http://127.0.0.1:埠/files/a.pdf` → 新分頁「a.pdf」、頁數正確。
- 伺服器用 302 轉到另一個網址、用 `Content-Disposition: attachment; filename="報告.pdf"` → 分頁名稱「報告.pdf」。
- 網址是 HTML 網頁 → 提示「不是 PDF 檔」、沒有新分頁；404 → 提示「下載失敗（404）」；`ftp://` → 紅字、〔開啟〕停用。
- 下載中按〔取消〕（伺服器慢慢送）→ 停止、沒有新分頁。
- 拖曳 `text/uri-list` 進視窗 → 開啟。
- Ctrl+Shift+O 打開視窗；剪貼簿裡的網址先填好。
