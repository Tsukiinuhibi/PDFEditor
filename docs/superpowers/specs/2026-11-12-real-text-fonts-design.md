# 修改原文選系統字型（v1.0.27）設計

日期：2026-11-12　狀態：待審

## 目標

v1.0.26 讓文字方塊可以選系統字型；這一版讓「修改原文」也可以。修改後的文字仍然是頁面上真正的文字（搜尋得到、複製得到），用到的字型以子集（只放用到的字）嵌入 PDF。

成功的樣子：
- 修改原文時格式列有「字型 ▾」，可以選這台電腦的字型，存檔後在任何電腦打開看起來都一樣（字型在檔案裡）。
- 修改原文時，原文用的字型如果這台電腦有，就自動用那個字型，改完的字和旁邊沒改的字看起來一致。
- 不能用的字型列出來但不能選，並說明原因。

## 使用者已決定的事

| 情況 | 處理 |
|---|---|
| 字型授權「禁止嵌入」（OS/2 `fsType` 有 Restricted 或 Bitmap only） | 列出但不能選，註明「授權不允許嵌入」 |
| 字型授權「不允許只嵌入用到的字」（`fsType` 有 No subsetting） | 可以選，但套用前跳出提醒：「檔案會增加約 N MB」，確定後才套用；存檔時整個字型放進 PDF |
| 直書 | 只有自帶直書資料的字型能選（`vhea`、`vmtx` 和 GSUB 的 `vert` 都要有）；其他註明「沒有直書資料」 |
| 選的字型裡沒有某些字 | 不自動替換。存檔前跳出提醒，列出缺的字，讓使用者選「這些字改用思源黑體」或「回去修改」 |

## 使用者看到的

**字型選單（修改原文時）**
- 和文字方塊同一個選單，多了兩種灰掉的項目：「授權不允許嵌入」「沒有直書資料」（只在直書時）。
- 選到「必須整個嵌入」的字型時，跳出提醒：「『〔字型〕』的授權要求把整個字型放進 PDF，檔案會增加約 N MB。要使用嗎？」〔取消〕〔使用〕。

**打開原文時**
- 原文的字型名稱（PDF 裡記的，例如 `ABCDEF+DejaVuSerif`）如果對得到這台電腦的字型，編輯器就用那個字型，格式列也顯示它。
- 對不到時照舊用思源黑體。

**存檔（Esc 或點空白處）**
- 有字型裡沒有的字時，跳出：「『〔字型〕』裡沒有這些字：〔最多列 20 個〕」〔回去修改〕〔這些字改用思源黑體〕。選「回去修改」，編輯器維持開著；選另一個就存檔，缺的字用思源黑體寫入。
- 連思源黑體都沒有的字（例如表情符號），照舊退回圖片做法（文字方塊）。

## 技術設計

### 1. 字型目錄多記三件事
`analyseFont` 另外取得：
- `embed`：`'ok'`／`'full'`（No subsetting）／`'no'`（Restricted 或 Bitmap only）。
- `vert`：有 `vhea`、`vmtx` 和 GSUB `vert`。
- `bytes`：字型檔大小（「檔案會增加約 N MB」用）。

快取鍵改成 `pdfeditor.fontcat.v2`，舊的 v1 結果沒有這些欄位，會重新分析一次。

目錄也記下每個家族所有字面的 PostScript 名稱和樣式（粗體字面、對應原文字型用）。

### 2. 取得要嵌入的字型檔
`systemFontBytes(family, bold)`：
- 從 `queryLocalFonts()` 找這個家族的一般或粗體字面，讀出檔案。
- 是 .ttc 字型集就拆出那一個字面，組成獨立的字型檔：複製它用到的表格，重寫表格目錄。
- 同一次執行內快取。
- 家族沒有粗體字面時，用假粗體：PDF 文字繪製模式 2（填色加描邊），描邊寬 0.03 em。

### 3. 修正 fontkit 子集化
`fontkit` 做 TrueType 子集時，若子集總長不超過 64 KB 就用短格式 `loca`（位移 ÷2）。原字型裡長度是奇數的字形會讓後面的字形全部錯位。

修法：程式啟動時替 `TTFSubset.prototype._addGlyph` 包一層，把奇數長度的字形補一個 0 位元組。這也適用於內建思源黑體（它已預先補齊，不受影響）。

CFF 格式（.otf）走 fontkit 的 CFF 子集；測試用 Inter 驗證。

### 4. 排版與寫入
`layoutReal`／`writePageText` 從「只有思源黑體」改成「每段文字自己的字型」：
- 字寬用該字型 fontkit 排版後的字形前進寬（不含字距調整，和 PDF 的寬度表一致），和編輯器（`font-kerning:none`）相同。
- 基線、行高和 v1.0.26 的文字方塊一樣：各字型的 ascent／descent 加上編輯器本身的字型（strut），同一行共用一條基線。底線位置、斜體傾斜沿用現在的比例。
- 每個用到的字型（含粗體字面）各嵌入一個子集，資源名稱記進區塊的 `PDFE_Fonts`，刪除區塊時一起清掉（現有機制）。
- 直書：用該字型的 `vmtx` 寫出 `W2`（每個字的直書前進量和原點）。原點 y 照 HarfBuzz（瀏覽器排直書用的引擎）的做法：有 `VORG` 用 `VORG`，否則每個字形用 `vmtx` 的 topSideBearing ＋ 字形 yMax，換算到 1/1000 em。

### 5. 原文字型對應
`pageTextItems` 已有每段文字的 pdf.js 字型。取出字型名稱、去掉子集前綴（`ABCDEF+`），比對目錄裡字面的 PostScript 名稱、或去掉空白後的家族名。對到的話，編輯器的根字型和每段 run 的 `font` 設成那個家族。

### 6. 缺字檢查
`realTextOK` 改成逐段檢查：每段 run 用它自己的字型（沒有 `font` 就是思源黑體）。

缺字分兩種：
- 指定字型缺、但思源黑體有：觸發上面的提醒。選「改用思源黑體」就把那幾個字拆成獨立的 run（`font:''`）再寫入。
- 連思源黑體也缺：照舊退回圖片做法。

### 7. 編輯器
- 修改原文時顯示字型按鈕與右鍵「字型…」。
- `htmlToRuns`、`currentTBStyle` 在修改原文時也記 `font`（目前固定為空）。
- `.tbed.real` 的預設字型仍是 `PDFE Sans`。

## 錯誤處理

| 狀況 | 處理 |
|---|---|
| 讀不到系統字型檔（被刪除、權限） | toast「讀不到字型〔名〕，這段文字改用思源黑體」，以思源黑體寫入 |
| 嵌入失敗（字型檔壞掉、fontkit 讀不了） | 同上 |
| 子集寫出後檢查有字形壞掉 | 改為整個字型嵌入；若仍失敗，用思源黑體並 toast |
| 對應原文字型時有多個候選 | 取 PostScript 名稱完全相同者，否則不自動選 |

## 測試（新增 `tests/e2e/edit-page-text-fonts.mjs`）

1. 用 DejaVu Serif 修改英文原文：
   - pdftotext 讀得到新文字。
   - PDF 裡有 `DejaVuSerif` 子集，且所有字形完整。
   - 頁面上和編輯器裡的寬度相同（±1 pt）。
   - 粗體使用 DejaVu Serif Bold 字面。
2. 用文泉驛正黑（.ttc）修改中文原文：拆出的字面可以嵌入，文字讀得到，字形完整。
3. 用 Inter（.otf，CFF 格式）修改英文：嵌入成功，文字讀得到。
4. 原文是內嵌 DejaVu Serif 的 PDF：打開原文時編輯器自動用 DejaVu Serif。
5. DejaVu Serif 加上中文：跳出缺字提醒，列出缺的字。
   - 「回去修改」：編輯器還開著。
   - 「改用思源黑體」：存檔成功，PDF 有兩個字型子集。
6. `fsType` 禁止嵌入、必須整個嵌入的字型：用測試字型檔（fonttools 改 `fsType` 的思源黑體小子集）驗證 `analyseFont` 的 `embed` 判斷；用假目錄驗證選單把前者灰掉、後者跳出大小提醒。
7. 直書：文泉驛（沒有 `vert`）和 DejaVu Serif（沒有直書資料）在直書時灰掉並註明原因。
8. 子集化修正：用奇數長度字形的測試字型（fonttools 不補齊）嵌入，檢查每個字形都完整。
9. 再次編輯保留字型；復原正常。

另外跑完整的 `npm run test:e2e`。

## 風險

- Windows 字型的 PostScript 名稱與 PDF 記錄的名稱寫法可能不同（例如 `MicrosoftJhengHei` 對 `MicrosoftJhengHeiRegular`）：對不到時只是不自動選，不會出錯。
- CJK 的 CFF 字型（例如思源黑體 .otf）測試環境沒有，只能用 Inter 驗證 CFF 路徑。
- 假粗體的粗細和瀏覽器的假粗體不會完全一樣。
