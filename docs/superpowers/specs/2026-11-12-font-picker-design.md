# 文字方塊選字型（v1.0.25）設計

日期：2026-11-12　狀態：設計已口頭核准，待審規格

## 背景與目標

使用者要的是讓文字方塊可以選字型，字型清單由軟體自己讀取系統的字型庫。這是三版計畫的第一版：

| 版本 | 內容 |
|---|---|
| **v1.0.25（本文件）** | 讀取系統字型清單；文字方塊可以選字型 |
| v1.0.26 | 「修改原文」也能選系統字型，存檔時嵌入 PDF（另寫規格） |
| v1.0.27 | 字型辨識：併入「文字辨識」，結果視窗分「文字｜字型」兩頁，列出可能的字型與相似度 %（另寫規格） |

使用者的要求是以穩定為優先，慢慢做。

成功的樣子：
- 文字方塊格式列有「字型 ▾」，能從這台電腦安裝的字型裡挑一個，反白的字就換成那個字型。
- 存檔後，在任何電腦、任何閱讀軟體打開，文字方塊看起來都一樣。
- 已經存在的文字方塊、舊版做的文字方塊都不受影響。

## 範圍

要做：
- 系統字型目錄（讀取、中文名稱、分組、快取）。
- 文字方塊格式列與右鍵選單的字型選單。
- 字型存進文字方塊的格式資料（`PDFE_RT`）、`RC`，以及外觀圖片。
- 文字方塊的預設字型改用內建的思源黑體（`PDFE Sans`），不再依賴網路上的 Google Fonts。

不做（留給 v1.0.26）：
- 「修改原文」選字型、把系統字型嵌入 PDF。這一版在修改原文時不出現字型選單。

## 使用者看到的

**格式列**
- 在「字級」前面加「字型［思源黑體 ▾］」。按鈕上的名稱顯示游標所在位置（或反白處）的字型。

**字型選單**（點按鈕後跳出，和顏色選單同一種浮動視窗）
- 最上面是搜尋框，打字即時篩選，中文名稱和英文名稱都能搜。
- 分組：
  1. 預設（思源黑體）
  2. 最近用過（最多 8 個）
  3. 中文字型
  4. 其他字型
- 每個名稱用它自己的字型顯示。
- 第一次打開時，還沒分析完的字型先用英文名稱顯示在「其他字型」，分析完會自動移到正確的分組、換成中文名稱。分析期間選單底部顯示「正在讀取字型…」。
- 讀不到系統字型時（例如功能被系統擋住），只列「預設（思源黑體）」並顯示「讀不到這台電腦的字型」。

**右鍵選單**：加「字型…」，打開同一個字型選單。

**套用規則**（和字級、顏色相同）
- 有反白的文字：只改反白的部分。
- 沒有反白、方塊是空的：整個方塊用這個字型。
- 沒有反白、游標在文字中間：從游標處開始，之後打的字用這個字型（和字級的做法一樣）。
- 沒有反白：同時成為之後新文字方塊的預設字型（記在 `pdfeditor.textbox.v1` 的 `font`）。

**這台電腦沒有該字型時**（例如別人在另一台電腦做的文字方塊）
- 頁面上的文字方塊照常顯示，因為外觀是存好的圖片。
- 再次編輯時，按鈕顯示「〔字型名〕（這台電腦沒有）」，編輯器暫時用思源黑體顯示。只要沒有換字型，存回去時字型名稱照樣保留。

## 技術設計

### 1. 字型目錄 `fontCatalog()`

- 用 Chromium 的 `queryLocalFonts()` 取得系統字型的每個字面（face）：`family`、`fullName`、`postscriptName`、`style`。已實測在本 App 的 Electron 中可直接使用，不會跳權限詢問。
- 依 `family` 分組。每個家族挑一個代表字面（style 是 Regular／Normal／Book／Roman 者優先，否則第一個）。
- 分析代表字面：`blob()` 取得字型檔，交給 `fontkit.create(bytes, postscriptName)`（.ttc 字型集靠 postscriptName 取出正確的那一個，已用 `wqy-zenhei.ttc` 驗證）。從字型檔取得：
  - **顯示名稱**：`name` 表的家族名稱，優先順序 `zh-TW` → `zh-HK` → `zh-MO` → `zh` → `zh-SG` → `en`。偏好 typographic family（nameID 16），沒有再用 nameID 1。
  - **是不是中文字型**：`hasGlyphForCodePoint` 檢查「中文字體」四個字都有。
- 快取：結果存在 localStorage `pdfeditor.fontcat.v1`，以 `family|postscriptName` 為鍵。下次打開只分析新的字型；已移除的字型自然不會出現在 `queryLocalFonts()` 的結果裡。
- 分析在背景進行，一次一個字型，避免同時把好幾個 20 MB 的中文字型讀進記憶體。每分析完一批就更新已打開的選單。
- 任何單一字型分析失敗（檔案壞掉、fontkit 讀不了）：該字型保留英文家族名，歸到「其他字型」，不影響其他字型。

### 2. 文字格式資料

- 每段文字（run）加一個欄位 `font`：CSS 用的家族名稱（`queryLocalFonts()` 的 `family`）。沒有這個欄位或空字串，就是預設字型。
- `htmlToRuns`：從計算後的 `font-family` 取第一個家族名；等於預設字型堆疊的開頭（`PDFE Sans`）就記成空字串。合併相鄰 run 時，`font` 也要相同才合併。
- `runsToHTML`、`richTextXHTML`：`font` 有值時加上 `font-family`。
- `runFont`（畫外觀圖片用）：`"〔font〕", 〔預設字型堆疊〕`，字型不存在時瀏覽器自動退回預設字型。
- 編輯器套用字型：`execCommand('fontName', false, family)`（已開啟 `styleWithCSS`，會產生 `<span style="font-family:…">`）。

### 3. 預設字型改用內建思源黑體

- 新常數 `TB_FONT = '"PDFE Sans","Noto Sans TC","PingFang TC","Microsoft JhengHei",sans-serif'`，給文字方塊編輯器（`.tbed`）與 `runFont` 使用。原本的 `FONT`（尺規等介面用）不變。
- `renderTextBox` 先等 `PDFE Sans`（以及用到的系統字型）載入完再畫，避免畫出退回的字型。
- 影響：沒有網路時，文字方塊原本會退回微軟正黑體；改了之後一律是思源黑體。字形設計和網路版的 Noto Sans TC 相同，已存在的文字方塊外觀圖片不變，只有重新編輯時才會用內建字型重畫。

### 4. 修改原文模式

- `openTextEditor({real:true})` 時，格式列和右鍵選單不顯示字型項目。
- `htmlToRuns` 在 real 模式下 `font` 一律為空，避免把 `PDFE Sans` 誤記成系統字型。

### 5. 相容性

- 舊的文字方塊沒有 `font` 欄位，視為預設字型。
- 舊版 App 打開新版做的文字方塊：忽略 `font` 欄位，顯示照常（外觀是圖片）。只有在舊版裡重新編輯時，才會變回預設字型。

## 錯誤處理

| 狀況 | 處理 |
|---|---|
| `queryLocalFonts` 不存在或丟出錯誤 | 選單只有預設字型，顯示「讀不到這台電腦的字型」 |
| 單一字型分析失敗 | 用英文家族名，歸「其他字型」 |
| 文字方塊用的字型這台電腦沒有 | 顯示「（這台電腦沒有）」，用預設字型顯示，字型名稱保留 |
| 字型選單開著時字型分析還在跑 | 選單即時更新，不會跳動到使用者正在看的位置（只在清單尾端或分組內插入） |

## 測試

新增 `tests/e2e/textbox-font.mjs`（測試環境有 DejaVu Serif、WenQuanYi Zen Hei／文泉驛正黑 等字型，後者是 .ttc 且有繁中名稱）：
1. 打開字型選單：列出系統字型；「文泉驛正黑」顯示中文名稱、在「中文字型」分組；DejaVu Serif 在「其他字型」。
2. 搜尋「文泉」只剩文泉驛系列；搜尋英文名稱也找得到。
3. 新文字方塊輸入文字，反白一部分換成 DejaVu Serif，送出：`PDFE_RT` 只有那段 run 帶 `font:"DejaVu Serif"`；外觀圖片和全部預設字型的版本有像素差異。
4. 再次編輯：那段文字仍是 DejaVu Serif，按鈕顯示正確名稱。
5. 沒有反白時選字型：成為預設，新的文字方塊沿用，「最近用過」出現該字型。
6. 缺字型：把 `font` 改成不存在的名稱後再次編輯，按鈕顯示「（這台電腦沒有）」，存回去名稱保留。
7. 修改原文時格式列沒有字型項目。
8. 快取：第二次開啟 App，選單立即有中文名稱（不必重新分析）。

另外跑完整的 `npm run test:e2e`，確認 textbox-basic、edit-page-text 等既有測試不受影響。

## 風險

- Windows 上中文字型檔很大（10～30 MB），第一次分析可能要幾秒：背景進行、一次一個、結果快取，所以只發生一次。
- `queryLocalFonts()` 回傳的家族名在 Windows 上是英文還是在地化名稱，這裡無法實測（測試環境是 Linux）：顯示名稱一律從字型檔讀，CSS 一律用 `queryLocalFonts()` 給的 `family`，兩者互不依賴。
