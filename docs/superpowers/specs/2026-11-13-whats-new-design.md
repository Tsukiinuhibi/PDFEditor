# 更新後顯示版本與更新內容（v1.0.29）設計

日期：2026-11-13　狀態：使用者已同意（「繼續做」）

## 目的
使用者：「可以先加入此次更新內容，每次更新完顯示版本更新跟更新內容」。更新後第一次打開程式，要看到現在是哪一版、這次改了什麼；「此次」（v1.0.28）的內容也要能看到。排在便利貼之前（簡單的先做）。

## 做法
- **採用**：程式內建版本記錄 `app/CHANGELOG.md`。離線也看得到，跳過好幾版也能一次列出。
- **不採用**：每次上網讀 Forgejo 發佈頁。沒網路就看不到，跳過幾版要讀好幾次。

## 設計
1. **版本記錄** `app/CHANGELOG.md`
   - 每版一段，標題 `## PDF 工作台 vX.Y.Z`，最新的在最上面。已從 git 歷史補回 v1.0.10–v1.0.28。
   - 發佈時把新版內容加在最上面，`RELEASE_NOTES.md` 放同一段。
   - `npm run check` 檢查：最上面一段的版本號＝`package.json` 的版本，內容＝`RELEASE_NOTES.md`。
2. **更新後第一次開啟**：localStorage `pdfeditor.seenversion.v1` 記錄上次看過的版本。
   - 記錄的版本比現在舊：跳出視窗「已更新到 vX.Y.Z」，列出比記錄新、到現在為止的每一版，新的在上面。
   - 沒有記錄，但這台電腦用過本程式（啟動時 localStorage 已有 `pdfeditor.` 開頭的鍵）：列出現在這版與前一版。v1.0.29 第一次出現時，因此也包含 v1.0.28。
   - 沒有記錄也沒用過（新安裝）：不跳視窗，只記下版本。
   - 跳出時就記下現在的版本，同一版不會再跳。
   - 按鈕：〔全部版本記錄〕（同一個視窗改列全部版本）、〔知道了〕。
3. **設定 → 軟體更新**：多一個〔更新內容〕按鈕，打開版本記錄視窗，列出全部版本，目前的版本在最上面。
4. **下載好、還沒重新啟動時**
   - 主程序檢查更新時，本來就讀到 Forgejo 最新發佈的資料，現在把它的 `body` 記下來。
   - electron-updater 沒給更新內容、而且是同一版時，就用 `body` 當內容。
   - 提示列原有的〔查看更新內容〕，以及設定頁的內容，因此會出現。
5. **Markdown 只轉這幾種**：`##`／`###` 標題、`- ` 清單、空行分段、`**粗體**`、行內 `` `code` ``。其他照原文字顯示（全部先跳脫）。

## 不做
- 不上網補讀舊版內容。
- 不做「不再顯示」選項。

## 測試（新檔 `tests/e2e/whats-new.mjs`，同一個使用者資料夾重開程式）
- 新安裝：不跳視窗，記下目前版本。
- 記錄的是舊版（例如 v1.0.26）：視窗標題「已更新到 v〔目前〕」，列出比 v1.0.26 新的每一版、不含 v1.0.26。
- 沒有記錄但用過：列出目前版本與前一版。
- 看過後重開：不再跳。
- 〔全部版本記錄〕與設定的〔更新內容〕：列出 `CHANGELOG.md` 的全部版本，第一個是目前版本。
- `npm run check` 的版本記錄檢查：用壞掉的暫存副本確認會報錯。
- 主程序的備用更新內容：測試環境沒有自動更新（開發模式），只能靠審查確認。
