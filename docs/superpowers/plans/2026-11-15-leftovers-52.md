### Task 1: 方向鍵微調的寫入
- `settleEdits`、`openInNewTab`：不管 `NUDGE` 有沒有值都 `flushNudge()`（它會等正在寫的 `NUDGE_RUN`），並且包在 try 裡。
- `copySelected`（Ctrl+C／Ctrl+X 複製頁面）：先寫入微調。
- `openDigiSign`：按下〔簽署並另存新檔〕之後、讀文件之前先 `settleEdits()`。
- 測試：align.mjs（寫入中再 `settleEdits`、微調後馬上 Ctrl+C）、signed-edit.mjs（微調後馬上數位簽章）。

### Task 2: 頁面文字與字型
- `fontBoxMeasurer`：Chrome 的半行距上半取 floor（量測：13 px 的思源黑體，canvas 模型的基線 13.95、Chrome 13）；下半是剩下的。
- `markOpenType`：CIDFontType0 不寫 `/CIDToGIDMap`。
- 清空的頁面文字編輯器：游標所在的 run 還是空的（只有零寬字元）時，再選字型或字級改它本身，不再包一層。
- 字型清單快取讀回時也帶 `variable`／`weight`。
- `pdfFontsIn` 的 `generic` 去掉多餘的 `!f ||`。
- 判斷：CID-keyed 但 charset 是 identity 的 CFF（少見、要 CJK .otf 與「不可子集」授權）；fontkit 的 CFF 子集 poppler 會記錯誤但畫得對（已量測）；「辨識文字中…」在讀 PDF 文字那一瞬間也出現（外觀）；`getRangeAt` 沒有範圍（`restoreTBRange` 會先 focus，一定有範圍）。

### Task 3: 設定檔
- `pdfeditor.export.v1`：已知的內部值（DPI 24～1200、品質 10～100、序號起始 0 以上整數、格式與範本是字串、勾選項是是非值）。
- 測試：在程式裡改檢視、文字方塊、樣式、轉存的設定後匯出，再讀回時一項都不略過。
