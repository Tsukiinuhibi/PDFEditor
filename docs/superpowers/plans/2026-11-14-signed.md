# 開啟有數位簽章的 PDF 時修改前提醒、處理中不接受快捷鍵（v1.0.46）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 開啟別人已經簽過的 PDF，第一次修改前提醒「修改後簽章會失效」；程式正在處理時，快捷鍵（Ctrl+W、Ctrl+Tab 等）不會關閉或切換分頁。

**Architecture:** 只改 `app/index.html`：
- `mutate()`：
  - 讀進來的文件還是加密的，就立刻停止，並說明原因。
  - 文件有簽章、而且這個分頁還沒問過，就先問；這個分頁按過〔繼續修改〕之後不再問。用分頁狀態 `sigChecked` 記錄。
- 新增 `signedDoc(doc)`：判斷規則跟 `pdfcrypt.js` 的 `isSigned` 一樣，找到任何簽章字典就算，但排除 `/Perms /UR3`、`/UR`。
- 快捷鍵處理（keydown）：`#busy` 顯示時不處理任何快捷鍵。

**Tech Stack:** pdf-lib 1.17.1、playwright-core e2e。

**Spec:** v1.0.45 最後檢查的發現：開啟的檔案不會設定 `S.signed`，所以修改有簽章的 PDF 時不會提醒；處理中 Ctrl+W／Ctrl+Tab 仍然有效。已排進 `HANDOFF.md` 的待辦。

## Global Constraints
- 介面文字用繁體中文（台灣）；commit 用英文，結尾加兩行 attribution。
- 分支 `wip/signed`。全部測試與最後檢查通過後，直接發佈 v1.0.46。
- 修改一律走 `mutate()`；不覆蓋原檔。
- 在程式內簽署後的提醒（`S.signed`，「此文件已數位簽署」）照舊，不要改。

## Review Focus
1. 只有使用權限（UR3）的 Reader 擴充表單不提醒；真正的簽章，不管欄位怎麼寫，都要提醒。
2. 按〔取消〕：文件不變，不留復原步驟，分頁不標成有修改；下次修改還會再問。
3. 在提醒視窗開著時，或處理中，不能關閉或切換分頁。
