# 尋找與取代（v1.0.39）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ctrl+F 尋找列（選項、標示、上下筆）、「搜尋」分頁、可選的掃描頁文字辨識，以及用「修改原文」機制的取代與全部取代。

**Architecture:** 全部在 `app/index.html`。`findLines(i)`：一頁的行（`pageTextItems` → `lineOf` → `joinRowPieces`，記下每個字屬於哪個 item），掃描頁（沒有文字）在勾選時用 Tesseract 讀（`ocrPageLines(i)`，依文件版本快取）。`searchDoc()` 在每一行的文字裡比對，得到 `hits`（頁、行、起訖、框）。標示畫在 `.ovl` 裡（`.fhit`），目前那筆 `.fhit.cur`。取代：同一行的符合處一起換，整行（或本程式的文字區塊）照修改原文重寫；全部取代在一次 `mutate` 裡做完。

**Tech Stack:** `app/index.html`（`pageTextItems`、`lineOf`、`joinRowPieces`、`editPageText` 的行與字型處理、`commitPageTextEdit`、`readPageBlock`、`ocrImage`、`ocrWorker`、`ocrSymbols`、`mutate`）、playwright-core e2e。

**Spec:** `docs/superpowers/specs/2026-11-13-find-design.md`

## Global Constraints

- 介面文字繁體中文（台灣）；commit 英文＋兩行 attribution；分支 `wip/find`；全部測試與最後檢查通過後直接發佈。
- 每次取代一次 `mutate()`：「已取代 1 處」「已取代 N 處」；全部取代只有一個復原步驟。
- 文案：「第 N／M 筆」「沒有找到」「辨識掃描頁…（K／M）」「辨識」「掃描頁的文字不能取代」「已取代 N 處」「掃描頁的 M 處沒有取代」。
- 選項存在 `pdfeditor.find.v1`：`{case, word, width, scans}`（預設 `{case:false, word:false, width:true, scans:false}`）。
- 快速鍵：Ctrl+F（開啟並選取輸入框）、Enter／Shift+Enter、F3／Shift+F3、Esc；Ctrl+F 加進 `RESERVED`。

## Review Focus

1. 修改或復原後標示與筆數立刻跟著更新（`loadDoc` 之後重新搜尋），不殘留舊框。→ Task 1 測試（取代後）。
2. 同一行有兩個符合處、全部取代：兩處都換、不會因為第一處換完位置變了而換錯。→ Task 3 測試。
3. 取代成比較長或比較短的字：同一行後面的字跟著移，不重疊。→ Task 3 測試（讀回整行文字）。
4. 本程式寫的文字區塊（修改過的行）再取代：格式保留、不會變成兩份。→ Task 3 測試。
5. 換分頁、關掉文件、開新文件時：尋找列的結果清空或重算，不會指到別份文件。→ Task 1 測試（換分頁）。
