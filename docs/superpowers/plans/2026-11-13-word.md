# 轉存成 Word（v1.0.42）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 輸出 ▾ 轉存 Word：把目前的文件（壓平我們的註解）轉成可編輯的 .docx；有 Word 用 Word 轉，沒有就用程式內建的轉換（文字段落、字級粗斜體、圖片、掃描頁文字辨識）。

**Architecture:** `app/index.html`：`flattenForExport(pages)`（pdf-lib 副本，把註解的 `/AP` 依 PDF 規格 8.1 畫進頁面內容）、`wordBlocks(page)`（pdf.js：文字行 → 段落、圖片、掃描頁 OCR）、`docxBytes(sections)`（OOXML＋`zipFiles`，pako `deflateRaw`＋CRC32）、`openWordDialog()`。`main.js`：`word:detect`（登錄 `HKCR\Word.Application\CurVer`）、`word:convert`（PowerShell＋COM，`DisableConvertPdfWarning` 暫時設 1）、`word:cancel`、`file:choose-save`、`app:open-path`。

**Tech Stack:** pdf-lib、pdf.js 4.10.38（`getTextContent`、`getOperatorList`、`commonObjs` 的字型名稱）、Tesseract.js（`ocrLines` 那一套）、pako 1.0.11（改成直接依賴）、Electron 45 `child_process.execFile`、playwright-core e2e。

**Spec:** `docs/superpowers/specs/2026-11-13-word-design.md`

## Global Constraints

- 介面文字繁體中文（台灣）；commit 英文＋兩行 attribution；分支 `wip/word`；全部測試與最後檢查通過後直接發佈。
- 原本的 PDF 與目前的文件都不改：壓平只在副本上；不進復原紀錄。
- 只寫使用者選的位置；暫存檔（Word 轉換用）轉完就刪。
- 文案：視窗「轉存成 Word」；「頁面」全部／指定；「轉換方式」用 Microsoft Word 轉換（最接近原本的版面）／程式內建轉換；「這台電腦沒有 Word」；「掃描頁先做文字辨識（可以編輯文字，比較慢）」；進度「轉換中：第 N／M 頁」「Word 轉換中…」；完成「已轉存成 Word：檔名」〔開啟〕；失敗「Word 轉換失敗：原因」〔改用內建轉換〕。

## Review Focus

1. 旋轉頁（/Rotate 90）與有 /Matrix 的外觀：壓平後位置對（Task 1 測試：旋轉頁上的文字方塊壓平後文字仍在 docx）。
2. 中文：段落接行不加空白、字型對應（細明體／正黑體／標楷體）、`xml:space="preserve"`、XML 特殊字元（`& < >`）跳脫（Task 1 測試的文字包含 `A&B <x>`）。
3. 很長的文件：記憶體與進度、〔取消〕立刻停（Task 2 測試：取消後沒有寫檔）。
4. 掃描頁判斷：整頁一張圖＋沒有文字 → 掃描；有文字層的掃描檔（已 OCR）直接用文字（Task 2 測試）。
5. Word 轉換：路徑含中文與空白、Word 跳出對話框卡住（逾時）、取消後 WINWORD.EXE 不殘留——Linux 測不到，只測介面（假的 `word:convert`）；實機確認記在 HANDOFF。
