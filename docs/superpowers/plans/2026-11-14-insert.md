# 修正：從其他 PDF 插入頁面（v1.0.44）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 插入視窗讀得到 PDF 包裡的 PDF、說明 XFA 表單；「限制編輯」的加密 PDF 可以插入、也可以直接開啟後修改。

**Architecture:**
- `pdfcrypt.js`（主程式，Node crypto＋pdf-lib 的 parser）：`decryptPdf(bytes)`，經 IPC `pdf:decrypt` 給畫面用。
- `app/index.html`：
  - `readablePdf(bytes)` 包住解密；`openInNewTab` 與 `insertFromPdf` 都先呼叫它。
  - `mutate` 失敗時不留下狀態。
  - `pagePicker` 多一個 `groups` 參數（段落標題）。
  - 附件分頁有〔開啟〕。

**Tech Stack:** Electron 45、Node crypto（md5、sha256/384/512、aes-128/256-cbc）、pdf-lib 1.17.1（`PDFParser`、`PDFObjectStreamParser`、`PDFXRefStreamParser`）、pdf.js 4.10.38（`getAttachments`、`getMetadata`）、pikepdf（只用來產生測試檔）。

**Spec:** `docs/superpowers/specs/2026-11-14-insert-design.md`

## Global Constraints
- 介面文字用繁體中文（台灣）；commit 用英文，結尾加兩行 attribution。
- 分支 `wip/insert`。全部測試與最後檢查通過後直接發佈 v1.0.44。
- 不覆蓋原檔。修改一律走 `mutate()`。
- 解密的規則跟 pdf.js 4.10.38 的 `CipherTransformFactory` 一樣：
  - 只試空白的開啟密碼。
  - 金鑰長度：V1–3 預設 40；V4/V5 用 `CF[StmF].Length`（小於 40 時單位是位元組）或 128。
  - AES 補位：最後一個位元組 ≤ 16，而且補位的位元組都相同，才去掉。
- 打包清單 `build.files`、`scripts/check.mjs`、`tests/e2e/whats-new.mjs` 的複製清單都要加 `pdfcrypt.js`。

## Review Focus
1. **解密結果悄悄錯了**（字串或串流亂掉，但沒有丟出錯誤）：每一種加密解開後，頁面的文字、Info 標題、註解內容、內嵌檔案都要跟原本一樣（Task 1）；開啟後畫出來的頁面要跟原檔一樣（Task 2）。
2. **有簽章的加密檔**：開啟時不解密、可以看；修改時顯示清楚的訊息（Task 2）。
3. **PDF 包裡的檔案有問題**：副檔名是 .pdf 但壞掉，或需要密碼：列為讀不到，其他檔案照常（Task 3）。
4. **跨段落、不連續的勾選**：依頁碼順序插入，每一頁來自正確的來源（Task 3）。
5. **大檔**：100 頁的 AES 加密檔要在合理時間內解開（Task 1：小於 5 秒）。

### Task 1: `pdfcrypt.js`、測試檔、IPC
**Files:**
- Create：`pdfcrypt.js`、`tests/e2e/fixtures/encrypted/make.py` 和它產生的檔案、`tests/e2e/pdf-decrypt.mjs`
- Modify：`main.js`（`pdf:decrypt`）、`preload.js`（`decryptPdf`）、`package.json`（build.files）、`scripts/check.mjs`、`tests/e2e/whats-new.mjs`

**Interfaces:**
- Produces：`decryptPdf(bytes) → Promise<{state:'plain'} | {state:'decrypted', bytes:Uint8Array, signed:boolean} | {state:'password'} | {state:'unsupported', reason:string}>`
- Produces：`window.desktop.decryptPdf(bytes)`，回傳同上。

- [ ] **Step 1：寫測試。** `make.py` 用一份來源檔產生下列測試檔：
  - 來源檔內容：2 頁文字（Helvetica，「Secret page 1/2」）、Info `/Title`（中文）、一個便利貼 `/Contents`、一個內嵌檔案、XMP metadata、文字欄位的值。
  - 加密方式：`r2-rc4-40`、`r3-rc4-128`、`r4-rc4-128`、`r4-aes128`（物件串流）、`r4-aes128-nometa`（EncryptMetadata false）、`r6-aes256`（物件串流）、`r6-userpw`（開啟密碼 `secret`）、`signed-aes128`（有 `/ByteRange` 的簽章字典）、`big-aes128`（100 頁）。

  測試要驗證：
  - 每一個測試檔：`state` 是 `decrypted`。
  - pdf-lib 讀解密後的結果時沒有 `/Encrypt`，而且文字、標題、註解、內嵌檔案、欄位值、metadata 都跟來源檔一樣。
  - `r6-userpw` 是 `password`；來源檔（沒加密）是 `plain`。
  - `signed-aes128` 的 `signed` 是 true，簽章的 `/Contents` 沒變。
  - `big` 小於 5 秒。
- [ ] **Step 2：執行，確認失敗**（沒有 `pdfcrypt.js`）。
- [ ] **Step 3：實作。**
- [ ] **Step 4：執行，確認通過。**
- [ ] **Step 5：Commit。** 訊息：`Encrypted PDFs: decrypt files that open without a password`。
